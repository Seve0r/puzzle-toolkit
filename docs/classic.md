# 古典密码工具箱

```bash
C=~/.dsh/skills/classic-cipher/scripts/classic.py
python3 $C <子命令> <文本>
python3 $C <子命令> --help     # 看该子命令的用法（也可用 -h）
python3 $C --help              # 全部子命令一览
```

| 子命令 | 作用 |
|---|---|
| `caesar` | 不给 `--key` 就 26 个偏移全爆破，按英文契合度排序 |
| `vigenere --key K` | 维吉尼亚；`--enc` 加密 |
| `vigcrack` | **无密钥自动破解**（自动定长 + 逐列解 + 密钥微调） |
| `affine` | 不给 `--a/--b` 就 312 种全爆破；`affine-enc --a 5 --b 8` 加密 |
| `sub` | 单表替换爬山破解（**需要 300 字母以上**，见下） |
| `bacon` | 培根，吃 `A/B` 串，也能从大小写隐写里读 |
| `railfence` | 不给 `--rails` 就全爆破 |
| `columnar --key K` | 列置换；不给 key 就按长度排列爆破 |
| `atbash` / `a1z26` / `polybius` | 直接解（`--enc` 转成编码） |
| `playfair --key K` | 普莱菲尔方阵 |
| `adfgx --key K [--trans T]` | ADFGX |
| `keyboard --all` | 键盘错位（qwerty/dvorak/azerty × 平移量） |
| `t9 <数字>` | 九宫格列出所有可能，按英文排序 |
| `auto` | 全部跑一遍汇总排名 |

## 编码方向（`--enc`）

**可逆的 12 个手法都支持双向**，加 `--enc` 就是加密：

```bash
python3 classic.py caesar --key 3 hello        # khoor
python3 classic.py caesar --key 3 --enc hello  # khoor（同上，加密方向）
python3 classic.py a1z26 --enc test            # 20 5 19 20
python3 classic.py keyboard --enc hello        # jrzzp
```

| 有编码方向 | `caesar` `vigenere` `affine` `bacon` `railfence` `columnar` `atbash` `a1z26` `polybius` `playfair` `adfgx` `keyboard` `t9` |
|---|---|
| **没有**（本身就是破解器） | `sub` `vigcrack` `auto` |

几个注意点：

- **`caesar` / `affine` 加密必须给参数**（`--key` / `--a --b`），不给会报错。
  不带 `--enc` 时它们是爆破器，输出的是候选列表。
- **`keyboard` 的 `--shift` 默认 `-1`**（往左还原，对应"手放错一格"）。
  `--enc` 取反方向。
- **`t9` 的输出有歧义**：`43556` 可以是 hello / hellm / …。短串靠 `t9` 穷举 +
  英文契合度就能挑回来，长串组合数会爆炸（本来也不该用 T9）。
- **`playfair` 有填充**：加密会补 `x`，解密需要 `--clean` 才去掉。这是设计，
  因为 `taxa`、`exe` 这类词和"补的 x"完全同形，没法自动判断。

## 从文件读输入

长密文不要往命令行里塞（尤其 `sub`，见下面的「长度红线」），用 `-f`：

```bash
python3 $C sub -f cipher.txt
python3 $C caesar -f cipher.txt
```

`-f` 读原始字节、按 UTF-8 宽松解码。文件不存在 / 是目录 / 无权限都直接报人话，
不会甩 Python traceback；路径支持 `~`，即使加了引号也能展开。

## 四个必须知道的坑（都是实测踩出来的）

**① chi² 在短文本上会反向误导。**
十几个字母的英文天然"每个字母各出现一次"，chi² 会判它**极不像**英文；而均匀分布的
乱码反而得分高。所以 30 字母以下 chi² 权重直接归零，只信 bigram。阈值随长度平滑过渡。

**② bigram 不能累加，必须除以长度。**
早期版本 `sum(bigrams) * 4`，结果"一半正确一半乱码"的文本得分比完美明文还高
（乱码凑出的 th/he/en/an 把分数顶上去），破解器专门挑假密钥。现在一律归一化。

**③ 维吉尼亚不能用 IC 判密钥长度。**
IC 对密钥的**整数倍**特别敏感——密钥 6 位时，12 位、18 位的 IC 一样高甚至更高。
按 IC 排序经常选出假长度，解出乱七八糟的"半通顺"文本。
正确做法：2..N 每个长度都完整解一遍按明文质量排名，最后用**最小周期**把
`secretsecret` 收敛回 `secret`。

**④ 逐列频率分析偶尔错一两个字母。**
某一列碰巧缺高频字就会解错。所以破解完必须对整段明文做一次**坐标下降微调**——
逐个字母试 26 种替换，保留整体得分最高的。加这一步后 9/9 密钥全中（不加只有 2/9）。

## 单表替换（`sub`）的长度红线

用词表做"能切成多少真单词"的覆盖率评分，比 bigram 强得多。
词表按顺序取第一个可用的：`PUZZLE_WORDLIST` 环境变量 → 仓库内 `data/words.txt`
→ 系统词典 `/usr/share/dict/words`（Linux / macOS）。Windows 上没有系统词典，
会用 `data/words.txt`；一份都找不到时会在 stderr 明确提示降级，不会静默变成纯 bigram。
但**词表信号在短文本上会反向误导**（错误映射也能切出一堆假词），
所以权重随长度增加，250 字母以上才给满。

实测：
- **330 字母 → 完美还原**（1 秒）
- **225 字母 → 失败**
- 132 字母 → 失败

结论：**少于 300 字母别指望自动解**，先看有没有线索能猜出部分映射（已知明文攻击）。

顺带：词表只认 3 字母以上的词。双字母词（in/at/do）在乱码里到处能凑出来，
会让乱码覆盖率虚高到 0.9，区分度直接没了。

## 填充与歧义（playfair / a1z26）

**`playfair` 默认严格互逆，不去填充。** 加密时相邻重复字母（`letter` 的 `tt`）
会插入 `x` 拆开，奇数长度末尾补 `x`，所以解密结果里会带着这些 `x`：

```
letter  --enc-->  ulszlkaz  --解密-->  letxterx
```

这是数学上正确的还原（原文 + 中间插入的 x + 末尾填充 x）。想直接拿原文就加 `--clean`：

```
classic.py playfair --key K --clean "ulszlkaz"    # -> letter
```

**`--clean` 有已知误伤**：原文本身含 `xax` 结构时会被一并删掉，例如 `taxa` → `taa`。
所以默认不清理——宁可多留痕迹，也不静默改动用户数据。

**`a1z26` 分两种输入，处理方式不同：**

- **有分隔符**（`"1 12 3"`、`"1,12,3"`）→ 每个数就是一个字母，绝不合并。
  早期版本在这里会贪心把 `1` 和 `12` 拼成 `22` → `v`，解出 `vc` 而不是 `alc`，已修。
- **连续数字串**（`"1123"`）→ 切分本身有歧义
  （`1-1-2-3` / `11-2-3` / `11-23` / `1-12-3`），枚举所有合法切分，
  按英文契合度取最好的那个。

## 猪圈密码（`pigpen`）

共济会密码（Masonic cipher），ARG/CTF 里那堆方块和三边形符号。

### 26 个图形怎么来的

**井字组 18 个**：3×3 网格里每格一个符号，画法是「该格子的边，但省略外边界」——
第 1 行不画上边、第 3 行不画下边、第 1 列不画左边、第 3 列不画右边。于是
左上格只剩右边和下边（`┘`）、中心格四条边都在（`□`）、右下格只剩上边和左边（`┌`）。
同一套 9 个形状各加一个中心点，就是另外 9 个。

**X 组 8 个**：正方形两条对角线切出四个三角，每个三角画两条指向中心的斜线
（上 `▽` / 左 `▷` / 右 `◁` / 下 `△`），再各加一个点就是带点的四个。

> 顺序「上、左、右、下」是历史惯例，**不是**顺时针。改成顺时针会让 S–Z 整段错位。

带点的点在**三角重心**（距中心 1/3 处），不是中心 —— 中心正好是四条斜线的交点，
点画上去会跟线粘成一团，符号越小越糊。

### 终端里怎么敲

猪圈符号没有 Unicode 编码，终端用近似字符代替：

| | 无点 | 带点 |
|---|---|---|
| 井字 | `┘ ⊔ └ ⊐ □ ⊏ ┐ ⊓ ┌` | 同左 + `·` |
| X 形 | `▽ ▷ ◁ △` | 同左 + `·` |

也可以直接敲槽位名：`g1`–`g9`（井字）、`gd1`–`gd9`（井字带点）、`x1`–`x4`、
`xd1`–`xd4`。连写 `g8g5gd3` 或加空格都行，近似字符和槽位名可以混着写。

### 变体

各变体用的是**同一套 26 个图形**，区别只在「按什么顺序填进 A–Z」。所以同一个
图形在不同变体里是不同字母，认错变体解出来就是一串看着像答案的乱码。

| `--variant` | 填法 |
|---|---|
| `original` | 井字 → 井字带点 → X → X带点（标准） |
| `rot-cross` | 同上，X 组内部旋转 |
| `grid-cross` | 井字 → X → 井字带点 → X带点 |
| `dotted` | 带点组整体提前 |
| `cross` | X 组整体提前 |
| `sandi` | 两组交替填（印尼叫 Sandi Kotak） |
| `sandi-rot` | 交替 + X 组旋转 |
| `agrippa` | 只用 18 个图形，缺 J K Q U |
| `labuse` | 缺 W X Y Z，X 组只用一半 |

认不出就先用 `original`，读不通再依次换。后两个变体碰到闲置图形输出 `?`。

### 词边界

编码时空格变成**双空格**（符号之间单空格），解码按双空格分段还原词界：

```bash
classic.py pigpen --enc "HELLO WORLD"   # ⊓ □ └· └· ⊏·  ▽· ⊏· ┌· └· ⊐
```

单空格**不**当词界 —— 题目里的符号本来就一个个分开写，按单空格分词会解出
`H E L L O`，比没空格更难读。

### 界面

「古典密码 → 猪圈密码」：参数区是 26 个可点的方块，**按图形几何位置排**
（井字就排成 3×3、X 组排成上/左/右/下），不按字母序 —— 看着题目找位置就行。

**没有「加密」开关**：输入里有符号就解成字母、纯字母就编成符号，边打边算。
输入框下方实时画出输入内容的图形，结果框下方按当前变体把字母画回符号，
用来跟原题逐格核对（两边应该长得一模一样）。

> 界面这块的符号形状来自 `classic.PIGPEN_SHAPE`，跟命令行同源。**不要**在前端
> 重写一份「哪个槽位画哪条边」——两份定义迟早分叉，分叉后界面点出来的符号跟
> 命令行认的不是同一个字母，而且不会报错。

## 推荐流程

1. `auto` 先扫一遍，看有没有直接中的
2. `caesar` 看 26 个候选（短文本尤其快）
3. 字母频率明显不像单表替换（IC 明显低于 0.0667）→ 上 `vigcrack`
4. 结果是 5×5 坐标、A/D/F/G/X 字母、或 AB/01 分组 → 分别是 `polybius`、`adfgx`、`bacon`
